# 持续优化（2026-10-10）

本轮承接已部署的审计修复，改进生产检查中发现的日志噪声、远程全表读取和备份保留工具。

## 修改

- 正常异步排队记录 INFO；实际调用飞书失败后的延后仍记录 WARNING。
- 飞书读接口支持过滤、字段投影和有界尝试；分页保留过滤条件，并拒绝重复分页令牌，防止循环。
- 预警闭环检查远程按设备过滤，只请求设备与闭环状态字段。本地活动事件短路和本地闭环复核保留；不缓存闭环结果，读失败仍抑制预警。
- Shadow 观察按设备过滤设备表与事件表，保留唯一设备检查、业务闭环和恢复时间的领域判断。注入的旧源保留兼容接口。
- 新增备份保留工具，默认只预览，保留最近 3 份且至少 30 天；手工/上线前快照、符号链接和带 SQLite 辅助文件的数据库不进入候选。显式 `--apply` 才删除，删除前再次核对大小、修改时间、inode 和辅助文件。

查询格式依据[飞书记录筛选指南](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/bitable-v1/app-table-record/record-filter-guide)。

## 验证

- 668 项 Python 测试通过，Ruff、JavaScript 异步回归和 diff 检查通过。
- 在生产容器以只读查询比较 11 台设备的事件筛选与原全表查询：结果完全一致。事件表当前 8 条记录；全表字段投影查询一次约 1303 ms，过滤查询分别约 995–1187 ms。这是单次测量，主要改善返回范围与未来数据增长，不宣称减少请求次数或保证固定延迟。
- 新工具在生产备份目录只执行预览：默认策略没有可删除候选。约 7.6 GB 既有备份继续保留，本轮没有清理生产备份或业务数据库。

运行示例：

```sh
python tools/backup_retention.py --directory data/backups
```

较大的手工/上线前快照需另行制定归档策略；不适合仅凭年龄自动删除。实时业务数据库的数据保留期限也未在本轮改动。
