# 温湿度控制操作手册

版本：交接用稿（2026-10-23）
适用人员：受控作业人员、仓库点检人员、区域责任人和异常处置人员

## 使用前准备

开始工作前，确认自己能访问飞书中的《设备温湿度记录》《环境标准表》《环境受控作业登记》《仓库环境点检记录》《环境异常事件表》和《异常处置闭环反馈》。作业登记的现有物理表带“试验”字样，正式入口及写入责任方须由现场管理员确认后使用。监控台可用于查看状态，但现场控制标准以经批准、当前有效的标准文件和标准表为准。

向上一班取得未闭环异常清单、临时控制措施、设备故障、人工测量安排和联系人。拿不到有效标准、读数或责任人时，先升级确认，不要把“无数据”视为“合格”。

### 本手册中的人员分工

| 人员 | 当班职责 |
| --- | --- |
| 当班操作/点检人员 | 读取、复核、登记、通知；记录所见事实和已采取的动作。 |

上述是操作分工，具体姓名、代理人和审批权限应填入第 10 节。台账中显示的默认责任人并不自动等于质量放行授权人。

| --- | --- | --- |

这些区域映射来自既有台账审计快照。若现场设备编号、区域或负责人变更，先核实当前台账，再更新手册。

## 1 接班检查

1. 打开《设备温湿度记录》或监控台，逐个查看负责区域的监测点。确认设备编号、区域、控制类型、当前温度、湿度、采样时间和在线状态。
2. 对“作业期间控制”的监测点，核对当前作业状态与现场是否一致；对“全天控制”的点，确认正在使用有效标准。
3. 查看《环境标准表》的标准编号、版本、生效时间、适用区域与工艺，以及温湿度上下限。任一必需限值为空，记录为“待工艺标准”并联系标准负责人。
4. 查看《环境异常事件表》的待处理、处理中及未闭环记录。按设备和异常开始时间逐条交接，记下责任人、已采取措施和下次复核时间。
5. 对设备离线、采样时间陈旧、读数缺失或明显异常的点，立即进行现场复核，记录现场仪表数值、时间和测量人。

建议按“设备编号 → 数据时间 → 在线状态 → 控制类型 → 作业状态 → 适用标准 → 温湿度 → 报警与事件”的顺序检查，防止先看数值、后发现数值属于另一设备或旧采样。数据新鲜度应同时关注最近测量时间和最近心跳时间：心跳证明设备仍有连接，但不代表刚产生了新测量。

### 标准核对细则

在《环境标准表》中按监测点、区域、当前工艺和当前时间找适用记录。核对“是否启用”“生效时间”“失效时间”“适用设备”“适用作业类型”“优先级”“标准编号”“版本”“来源文件”，再读取四个限值。设备专用标准优先于区域默认标准，工艺专用标准优先于通用标准。同层级同优先级出现冲突时，联系标准负责人确认，不自行选择对当前读数有利的一条。

标准表中现有 TH-01～TH-11 的记录属于历史限值迁移；正式标准编号、版本、生效时间和来源条款仍需业务确认。它们即便显示“已启用”，也不能替代来源文件审批。现场人员不应直接修改旧版本上下限；标准变更须经批准、形成新版本并保留生效记录。

### 判定顺序

1. 温度或湿度离线，先判“设备离线”并进行人工复测。
2. 数值缺失或非法，判“数据异常”，不得跳到正常或超限结论。
3. 控制类型为“仅监测”，或“作业期间控制”但当前不在“作业中”，显示“仅监测”；仍需关注明显异常读数。
4. 应受控但缺少适用限值，显示“待工艺标准”。
5. 数据有效、标准适用时，温度和湿度都落在各自上下限的闭区间内才为“正常”；任一越界为“超限”。

显示结果是系统状态。现场判断还应考虑仪表可靠性、作业/物料实际情况和现行受控文件。

| 看到的状态 | 当班动作 |
| --- | --- |
| 正常且数据新鲜 | 按本班点检频次继续监测。 |
| 仅监测 | 继续观察趋势与设备状态；不得据此证明环境合格。 |
| 待工艺标准 | 联系标准负责人确认，受控作业不得凭空限值放行。 |
| 超限 | 立即执行第 4 节，不等待自动报警。 |
| 设备离线、数据缺失或异常 | 现场测量并执行第 5 节。 |

## 2 受控作业登记

适用于 TH-03、TH-04、TH-05、TH-07。登记前确认监测点与区域一致，工艺有对应有效标准，当前温湿度与数据质量满足现场作业要求。是否暂停或停止作业，由现场质量和安全制度及授权人员决定。

### 开始作业

1. 核对设备编号与区域、现场拟执行的工艺、有效标准、当前数据时间、温湿度、在线状态和未闭环事件。存在异常时先按第 4 或第 5 节处理，并取得有权人员的决定。
2. 在经现场确认的《环境受控作业登记》入口选择“开始作业”，填写监测点、区域、工艺及登记要求的时间、人员信息；工单号有则填，无则留空。当前试验物理表尚无工单号字段时，不要将登记编号填作工单号。
3. 提交后看“登记组合校验”是否为“有效”，并核对《设备温湿度记录》中的“当前作业状态”为“作业中”、当前工艺与登记一致、作业开始时间正确。
4. 再查看作业区间记录是否生成，开始时的温湿度、在线状态与判定是否已留痕。若任一步没有同步，记录登记记录号和时间，通知台账管理员并按现场受控流程处理。
5. 组合校验失败时，核对设备、区域和工艺后重新登记；不要手改旧记录冒充有效状态。

### 工艺切换

1. 切换前确认新工艺的有效标准、当前环境和已打开的作业区间；记录切换前的状态。
2. 选择“工艺切换”并填写新工艺与时间；核对旧区间状态为“工艺切换结束”，新区间状态为“作业中”，主表当前工艺和作业开始时间已更新。
3. 再核对切换后的适用限值，确认判定与新标准一致。若标准尚未生效、登记校验失败或主表状态未更新，联系登记/标准负责人，不以旧工艺限值判断新工艺。

### 结束作业

1. 确认现场作业实际结束，再选择“结束作业”并提交登记。
2. 核对主表显示“无作业”、当前工艺为 N/A、作业开始时间已清空，开放区间已标记“已结束”并记录结束时环境快照。
3. 再核对该作业期间产生的异常事件。结束登记只清理尚在“计时中”的警报，不自动关闭已发出的环境异常；将未闭环事件交给责任人继续处理。

### 作业登记常见异常

| 情形 | 操作 |
| --- | --- |
| 组合校验显示错误 | 检查“监测点—区域—工艺”组合；保留错误记录供审计，重新提交正确记录。 |
| 主表未变为“作业中” | 检查登记是否成功和工作流是否执行；记录时间、登记编号并通知管理员。 |
| 出现较旧登记覆盖当前状态 | 保留两条记录及创建时间，联系管理员核实；勿直接改写历史区间。 |
| 作业超过 6 小时未结束 | 根据提醒核对是否仍在作业；继续则确认责任和记录，已结束则及时登记结束。 |
| 作业期间发生超限 | 先按第 4 节现场处置；作业状态变更不能代替异常事件闭环。 |

## 3 仓库环境点检

适用于 TH-08 防爆仓库、TH-09 仓库、TH-10 PE 仓库、TH-11 设备区。现有提醒在工作日 10:00 发出并要求 12:00 前完成；现场排班、节假日和替班要求以负责人确认的制度为准。

1. 到现场核对区域、监测点和仓储实际状态，查看当前温湿度、采样时间、在线状态及当前适用标准。检查现场仪表、空调/除湿等控制设施是否按区域要求运行；设施检查项目以现场制度为准。
2. 与上一条点检记录比较读数、现场状态和遗留异常；明显跳变或数据失效时用现场仪表复测，并写明仪表编号和测量时间。
3. 在《仓库环境点检记录》中如实填写“现场仓储状态”“监测系统状态”“未闭环环境报警”和“异常说明”。系统快照可能回填点检时温湿度、在线状态、环境判定和报警状态；提交后仍要核对快照与实际监测点一致。点检人、点检时间由系统生成时核对其正确性。
4. 如发现现场异常、监测离线或未闭环报警，查找同一区域、同一设备现有事件，通知责任人，记录现场处置与下次复核时间。资料显示“点检异常自动建事件”工作流停用，不能假定提交点检就已生成事件。
5. 核对记录已保存，主表“最近仓库点检时间”已更新；若未更新，保留点检记录并通知台账管理员。

### 点检记录出现异常时

“现场仓储状态=发现异常/待跟进”“监测系统状态=离线/数据异常”或“未闭环环境报警=有/待确认”都需要继续追踪。先确认有无同设备、同异常开始时间的事件，再按现场流程补充或上报；不要为了得到一个事件编号重复创建同一报警周期的事件。点检表中的“异常/报警编号”字段类型与 ENV 文本编号存在不一致，不能手工把 ENV 文本硬填进数字字段。

## 4 温湿度超限处置

1. **立即核实**：记下监测点、区域、发现时间、温度和湿度、采样时间、适用标准版本、作业状态；与现场仪表对比。
2. **现场控制**：按区域现行安全/质量文件采取措施并通知责任人。需要停工、隔离产品或调整设备时，由有权限人员决定和执行。不要等自动化完成确认才采取现场行动。
3. **持续观察**：系统规则是连续超限 5 分钟后复核并形成正式警报。查《环境异常事件表》，核对事件编号、开始时间、峰值、责任人和控制要求。若没有自动事件，按现场异常上报流程登记并通知系统维护人员。
4. **查因与复测**：记录原因、采取的措施、涉及的作业或物料、复测时间及结果。
5. **确认恢复**：系统以持续正常 1 分钟复核恢复；查看事件中的恢复时间。环境恢复只是监测事实，事件仍需人工闭环。
6. **完成闭环**：责任人通过《异常处置闭环反馈》补齐原因、措施、产品影响、恢复及关闭资料，核对事件最终显示已闭环。

同一设备可能有不同开始时间的多条未闭环历史事件。按事件编号和开始时间逐条核对，不因当前读数正常就批量关闭。

### 报警状态和人工动作对照

| 报警/事件状态 | 含义 | 现场动作 |
| --- | --- | --- |
| 未触发 | 尚无待复核正式警报 | 仍以现场实测与标准判断，发现越界立即处理。 |
| 计时中 | 系统已发现越界，正在等待持续性复核 | 立即控制与核实，连续观察，保留发现时刻。 |
| 已发警报 | 持续超限复核通过 | 查找对应 ENV 事件，落实责任、措施和影响评估。 |
| 事件待处理/处理中 | 事件存在，仍需人工处理 | 更新处置进度与复测结果。 |
| 恢复时间已填 | 环境恢复被记录 | 继续完成原因、措施、影响和关闭确认。 |
| 闭环状态为已闭环 | 业务事件关闭 | 核对资料齐全，归档至交班或月度复盘。 |

若 5 分钟后仍越界却没有事件，应先确认责任人字段、自动化运行状态和既有事件，再通知管理员；不能把“无事件”当成“无异常”。若收到同一设备同一开始时间的多个事件，记录编号并交管理员核查重复，现场只围绕真实异常采取一次一致的处置。

### 闭环前逐项核对

- 事件编号与监测点、异常开始时间一致；
- 记录了原因、纠正或临时措施、复测结果及时间；
- 评估了受影响的作业、产品或物料，写明结论与批准人；
- 恢复时间、关闭时间及处理人正确；
- 飞书显示的最终“闭环状态”为“已闭环”。“关闭完整性校验”或温湿度恢复不应单独作为闭环证明。

现有资料显示事件超过 24 小时未关闭会提醒，资料不完整也会提醒。提醒不能代替责任人的主动跟踪。

## 5 离线、缺值和读数异常

1. 记录监测点、故障发现时间、最后一条有效读数与时间。
2. 用合适的现场仪表测量并记录数值、测量位置、仪表编号、测量人和时间；按现场要求增加人工测量频次。
3. 联系设备或系统维护人员排查传感器、供电、通信与数据映射；期间按现场受控要求判断作业或仓储是否可继续。
4. 修复后核对新读数、采样时间、在线状态和现场仪表的一致性，记录恢复时间；再结束临时人工测量。

### 区分测量与心跳

测量变化上报更新“最近测量时间”和样本历史；约每分钟的心跳用于证明设备仍在线，不生成新的测量历史。一段时间内数值不变但心跳新鲜，可能是环境稳定，也可能需要现场复测；若收到“unavailable”或“unknown”，应即时按离线处理。仅凭旧的最近测量值不能判断当前环境。正式采用的“陈旧”时间阈值和人工补测频次需由现场负责人填入第 10 节。

## 7 三个操作示例

### 示例一 作业开始前显示“待工艺标准”

TH-04 拟开始受控作业，主表显示“待工艺标准”。操作员先核对当前工艺、设备编号、区域和标准有效期；联系标准负责人确认正式版本。登记系统状态与现场实际情况，并按现场授权流程决定是否允许开始。不要根据另一设备或历史快照抄一个限值。

### 示例二 仓库出现越界

TH-10 点检发现温度越出当前有效上限。点检人记录时间、读数、标准版本和现场复测值，立即通知区域责任人并按现场制度采取控制措施。随后观察系统是否进入“计时中”；连续 5 分钟复核后核对 ENV 事件。环境恢复并满足 1 分钟复核后，继续补齐原因、措施和受影响物料评估，直到事件显示已闭环。

### 示例三 设备离线但旧读数正常

TH-08 主表保留上一条正常读数，但设备当前离线。点检人不能据旧读数认定仓库合格，应以现场仪表测量并记录，联系维护人员，按规定频次补测。通信恢复后核对新读数与现场值一致，再关闭临时测量安排。

示例只演示动作顺序；具体停工、隔离和放行条件由现场受控文件决定。

## 8 记录质量要求

记录事实时使用“测量时间”和“记录时间”两个概念；补录应标明实际测量时间。温度使用 °C、湿度使用 %RH，并注明现场仪表和测量位置。涉及两个监测点的同一区域，例如通用总装线 TH-05 与 TH-06，不得只写区域名。更正错误记录应保留原记录与更正原因，避免覆盖追溯链。异常沟通应至少包含设备、时间、数值、标准版本、当前控制状态、已采取措施和下一次复核安排。

## 10 温湿度标准维护

本节供**有标准维护权限的人员**使用。现场操作员发现标准不适用时提交变更需求，不自行改限值。系统的生产判断读取飞书《环境标准表》经完整校验后的有效快照；《设备温湿度记录》中的“当前适用上下限”只是展示结果，监控台的控制区间也是只读展示。不能通过修改这些展示值改变正式标准。

### 10.1 何时提出维护

出现以下情况，应发起标准核查或变更：工艺文件或质量要求换版；区域、设备或工艺适用范围改变；新增监测点；有效期即将届满；运行状态显示“待工艺标准”；同一区域多个候选标准互相冲突；现场批准限值与系统显示不一致。紧急临时控制也应先取得有权限人员的书面决定、适用范围和期限，再由标准维护人员形成可追溯版本。

### 10.2 变更前准备

1. 收到标准来源文件、文件编号和条款、批准人、批准日期、计划生效时间。确认文件确实适用于目标区域、设备和工艺。
2. 列出受影响的监测点、当前作业或仓储活动、旧标准编号和版本、旧限值、新限值及变更原因。通用总装线同时有 TH-05 与 TH-06，不能只按区域名推断两个点都适用。
3. 与区域责任人确认切换窗口。若新标准会改变“正常/超限”判定，提前安排生效时段的现场复核和异常跟踪。
4. 由批准人确认是否需要对在制品、库存或已发生的异常作影响评估。标准维护人员不得仅为消除当前警报而调整限值。

### 10.3 飞书标准记录字段填写

打开[NoEE 温湿度监测台账](https://qjvasb3rm2.feishu.cn/wiki/PKKJwvD8ei7zL3k3Dbkcj2S8nhc?table=tblc6uCFLGPZLcR6&view=vewo6x1Acl)，在同一个 Base 中切换到《环境标准表》并新增记录或新版本；《设备温湿度记录》是设备当前状态表，不是标准录入表。按以下字段逐项填写，并与批准文件逐项比对。只有有标准维护权限的人员可编辑标准。

| 字段 | 填写与复核要点 |
| --- | --- |
| 标准编号 | 同一逻辑标准后续修订沿用原编号；新控制要求才建立新编号。 |
| 版本 | 每次业务内容变更使用新版本；相同“标准编号＋版本”的内容不得原地覆盖。 |
| 适用区域 | 使用当前设备台账的正式区域名称，避免简称、空格或同义名称不一致。 |
| 适用设备 | 当前运行时完整快照校验要求必填，填写《设备温湿度记录》中的唯一设备编号。不要留空建区域默认标准；虽然解析器支持区域级默认概念，本部署的同步校验会拒绝空设备编号。 |
| 适用作业类型 | 工艺专用标准填正式工艺名称；留空表示该区域/设备的通用标准。 |
| 控制类型 | 必填，使用 `全天控制`、`作业期间控制` 或 `仅监测`，并与批准范围及设备台账的控制用途核对。 |
| 温度下限、上限（°C） | 当前完整快照校验要求两项均为有限数字，即使某设备标为“仅监测”也不能留空。只能从批准文件填写；下限必须**小于**上限。没有批准温度范围时，不得编造数值，应先由系统维护人评估同步契约如何调整。 |
| 湿度下限、上限（%RH） | 同温度，当前校验也要求两项均有值且下限**小于**上限。不得只填单侧限值或把百分数误写为小数比例。 |
| 生效时间、失效时间 | 生效时间必填并填写有明确时区含义的切换时点；生效时间包含该时刻，失效时间不包含该时刻。持续有效可不填失效时间。 |
| 优先级 | 同类候选标准数字越大越优先；不能用随意提高优先级掩盖重复或冲突。 |
| 是否启用 | 草稿留在审批资料中，不进入同步表；批准记录首次进入同步表时填写批准状态。未来生效记录以启用状态录入，并用生效时间控制切换。 |
| 来源文件、条款 | 记录正式文件编号、版本和具体条款；备注不能代替来源文件。 |
| 最后确认人、备注 | 记录审批和变更背景，便于追溯；这两个字段不参与规则解析。 |

代码 Adapter 还要求飞书标准表提供 `控制类型` 字段，但目前映射清单没有记录该字段的飞书 field ID。新增记录前先让台账管理员确认《环境标准表》中该字段存在且选项为上表三个值；如果字段缺失或字段名不符，先由系统维护人修正表结构/映射并做成功同步，再录入正式标准。

温湿度边界值本身包含在合格范围内。例如“20～26 °C”表示测得 20 °C 与 26 °C 均在范围内；这里只解释比较规则，**不是任何监测点的正式限值**。显示和判定可能有小数位处理，接近边界时以批准文件、系统规则和现场复测共同核对，不靠手工估算。

### 10.4 新版本和适用范围冲突检查

1. **修订原标准**：沿用 `标准编号`，创建新 `版本` 和新的生效时间。不要把旧版本的上下限、适用区域、设备或工艺直接改成新值；旧记录用于历史追溯。
2. **新增独立标准**：只有业务上确实是另一项标准时才建立新编号。先检查是否与现有记录在区域、设备、工艺和生效期内重叠。
3. **检查候选关系**：先看是否启用且在有效期内，再看区域、设备、工艺和优先级。当前同步校验要求每行都带设备编号；本部署新增标准按目标设备逐条绑定，不建立空设备编号的区域级标准。同一匹配层级、同优先级若仍有多条候选，属于配置冲突。
4. **检查版本时间**：同一标准编号的两个版本不能使用相同生效时间；区域、设备、工艺等适用范围变化且有效期重叠时，系统可能拒绝整个快照。变更适用范围前要与管理员设计好旧版失效和新版生效时点。
5. **检查覆盖范围**：确认新旧版本衔接后，所有应受控设备仍有可解析的有效标准；不能为一个设备改动导致其他设备失去标准。

既有 TH-01～TH-11 的 `ENV-LEGACY-TH-*` 属于历史限值迁移记录。维护人员应先核对正式来源和版本，再决定如何形成正式标准链；不能把迁移标识直接当作已审批的文件编号。

### 10.5 提交、生效和核验

1. 填好记录后请另一名有权限人员复核来源文件、目标设备、工艺、单位、上下限、时间、优先级和启用状态，并保留审批记录。
2. 双人复核完整字段后，再将最终记录加入同步表，并在首次同步时填写批准的启用状态。已同步的 `(标准编号, 版本)` 包括启用状态、上下限和有效期在内均为不可变业务内容；不要先同步停用记录再改为启用。未来生效记录保持批准的启用状态，使用批准的未来生效时间安排切换。系统通过周期性标准同步读取**完整标准表快照**，只有整份快照校验成功才会激活。表格显示已保存，不等于监控系统已经采用新版本。
3. 由系统维护人员查询带权限的系统状态，核对最近标准同步成功、`standards_ready`、有效快照、已验证设备数量和标准来源；需要时再查只读 `/api/thresholds`，确认目标设备返回 `authoritative_source=feishu` 及预期版本/限值。
4. 现场人员在《设备温湿度记录》或监控台核对受影响点的“当前适用上下限”和判定，并查看一条新采样或现场复测。核对同一区域其他点未被误改。
5. 将生效时间、系统同步成功时间、检查人、现场复测及异常处理情况写入变更记录，通知相关班组。正在处理的环境异常仍按原事件编号继续追溯，不因标准版本变化自动视为闭环。

如果同步失败，系统保留上一次通过校验的快照；首次同步前可能没有可用标准。此时应修正错误记录并重新确认同步，**不能因为飞书记录已更改就宣称新限值已生效**。若错误版本已生效，应先按现场变更和风险评估流程处理，再用正确的新版本/有效期安排修正，保留历史审计；不要直接抹去既有版本。已经同步记录的停用、撤销或适用范围调整没有原地修改通道，操作前须由系统维护人设计新版本和完整快照迁移，确保其他设备标准覆盖不受影响。
